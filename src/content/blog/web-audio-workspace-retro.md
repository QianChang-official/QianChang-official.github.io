上周五晚上我在自己博客上听歌，切了个 EQ 预设，歌直接停了。再点播放，声音闷闷的，还带着一股电流杂音，跟打电话似的。

我一开始以为是音源文件坏了，登到 R2 后台一播，好家伙，干净得很。问题出在前端。

## 先修"切 EQ 就停"

这个最好找。控制台里挂 `<audio>` 的容器用的是 React 内联 ref，每次 setState——切 EQ、动滑块、甚至状态栏文字变一下——都会重渲染，旧代码在 ref 里对同一个元素又调了一遍 `load()`，直接重载媒体流。

改成稳定的 `useCallback`，元素只挂一次，完事。

## 真正的怪病：电流声

暂停修好了，但声音还是不对。不管开不开 EQ、开不开环绕，都是一股电话音，还夹杂音。

我对照着重构前的旧版代码一行行比，最后锁定到一行看起来特别无辜的代码：

\`\`\`ts
sourceNode.connect(analyserIn);      // 处理链路
sourceNode.connect(ctx.destination); // ← "兜底"直连
\`\`\`

第二行本来是"引擎没接好也能出声"的兜底，实际效果是把**干声和处理后的湿声在输出端叠在了一起**。这一叠就出事了：

干+湿叠起来大约 +4.7dB，FLAC 大动态的地方直接顶破满幅——这就是电流声的真身，数字削波的爆音。同时干声和经过 EQ/环绕相位偏移的湿声一混，频响被挖出一排等间隔的坑——这就是通话感的来源，梳状滤波。

把那行直连删掉，恢复单一处理路径，声音立刻干净了。说实话我当时盯着那行代码看了三分钟，就一行，杀伤力这么大。

## 环绕处理器自己的毛病

环绕那块也不干净。它把立体声拆成中置和差分，对差分做滤波、Haas 延迟再反相混合。问题在于：

- 每个渲染量子（128 个采样）都重新 new 一遍滤波器系数对象——在音频线程疯狂制造 GC 压力，全是细碎爆音；
- 整数延迟线 + 参数硬切——拖延迟滑块的时候咔哒咔哒响。

修法：系数只在截止频率变化时才重算、延迟线改成线性插值的小数延迟并逐采样平滑、开关加 4ms 交叉淡化。改完之后所有参数随便拖，干干净净。

## 最阴的一个：换页就停

这个折腾了我最久。Astro 的 ClientRouter 切页的时候，浏览器会**异步**把正在播放的媒体元素暂停掉——没有 JS 调用栈、pause 事件可能在换页完成后才派发、元素 \`isConnected\` 还是 true。\`transition:persist\` 保住了 DOM 节点，保不住播放状态。

最后解法是两层：模块加载时就把元素挂到 \`document.body\`（display:none，永不卸载），再注册模块级的 \`astro:before-swap\` / \`astro:page-load\` 监听——换页前记一下"刚才在播"，换页后带重试地无缝 \`play()\` 回来。因为挂在模块层不在组件里，所以不受岛屿重挂载时序影响。

现在站内随便切页，最多有个听不出来的亚秒衔接，进度条连续走。

## 顺手压了下延迟

从"点播放"到"听到声音"这条链路也捋了一遍：\`<head>\` 里给 R2 域和 Worker 加 \`preconnect\`（必须带 \`crossorigin\`，不然预热连接进的是另一个池子，CORS 请求用不上）、\`AudioContext\` 用 \`latencyHint: 'interactive'\`、首个 \`pointerdown\` 就唤醒上下文不等 \`play\` 冒泡。悬浮播放器原来还藏了第二个 \`<audio>\` 当进度条用，每首歌被完整下载两遍，换成绑定共享元素的滑条，顺带加了音量控制。

## 收尾

这套东西最后的效果是：FLAC 边下边播、EQ/环绕实时调节不中断、换页不断、延迟压到最低。浏览器音频的坑基本都踩在"隐式行为"上——自动重载、异步暂停、并联混音——没有一行报错，但每一行都在出声。

源码在 [GitHub](https://github.com/QianChang-official/QianChang-official.github.io) 的 \`src/components/audio/\` 下，[音源页](/audio)可以直接玩。
